# 오디오 출처 및 검증 · 2026-11-09

## 적용
- 콩이 / 힘 실험실. 기존 Kenney Interface Sounds CC0 효과음 보존, 음소거·숨김 탭 재생 방지.
- src/npc-narration.js: 기존 NPC 안내 영역의 수동 인사 듣기/중지, AI 합성 표시, 별도 인사 자막, 48px 컨트롤. 한 플레이어만 사용하며 다른 조작·패널 제거·탭 숨김·영상 재생 시 중지한다. 기존 배경 음악은 발화 중 일시정지 후 복원한다.
- 기존 효과음 켜기/끄기를 따르며 NPC 음량은 npc-narration-volume에 별도 저장한다. 손상된 저장값은 기본값으로 복구하고 범위를 제한한다. 학습 기록과 판정은 바꾸지 않는다.
- 신규 녹음은 환영 인사 1개다. 모든 동적 힌트를 녹음한 것은 아니다. 기존 힌트 자막은 그대로 남는다. 마이크, 음성 인식, 원격 TTS, 기기 음성 fallback은 추가하지 않았다.

## 신규 음성의 출처
- assets/audio/npc-welcome.mp3 (원본은 public/ 아래).
- 직접 로컬 실행한 Qwen/Qwen3-TTS-12Hz-1.7B-CustomVoice, 기본 합성 음성 Sohee. 개인 녹음 복제 없음.
- 모델 리비전 0c0e3051f131929182e2c023b9537f8b1c68adfe, 모델 표시 라이선스 Apache-2.0.
- 모델 출처: https://huggingface.co/Qwen/Qwen3-TTS-12Hz-1.7B-CustomVoice/blob/0c0e3051f131929182e2c023b9537f8b1c68adfe/README.md
- 실제 대본·시드·생성 설정·런타임 SHA-256은 audio-provenance.json, 원 생성 기록은 audio-generation-original.json에 보존했다.
- 모델 라이선스와 출력물의 권리 판단은 구분한다. 모든 권리가 없다는 의미의 “저작권 없음”이나 무조건적인 면책을 주장하지 않는다. macOS say 녹음은 사용하지 않았다.

## 검증
- macOS arm64 / Node v24.22.2. 기존 단위 테스트: #1 194/194, #2 220/220, #3 154/154, #4 175/175.
- 해당 프로젝트의 최종 build 성공. #1 TypeScript 포함, #2–4 check 성공.
- 실제 Chrome, 격리된 로컬 페이지: 실제 MP3의 currentTime 증가, 정지 후 시간 0, 음량 0 중지 확인.
- 별도 모의 Audio 브라우저 회귀: 재생/중지, 다른 조작, 패널 숨김, 효과음 꺼짐 차단, 음량 저장 확인.
- 실제 사람의 발음·음질 청취, 실제 iPad/Android 기기 검사는 미실시. #1·3은 신규 환영 MP3 하나만 precache와 캐시 응답 예외로 추가했으며 다른 스트리밍 정책은 유지했다. #4도 서비스워커 목록에 포함한다. #2는 서비스워커 없음. 네 프로젝트 모두 최종 dist MP3와 원본의 SHA-256 일치 확인.
- 각 프로젝트 graphify update . 완료. 커밋·푸시·배포 없음.
- 실제 게임의 정상 시작/첫 장소/힌트 UI를 통해 대표 안내자 인사 버튼과 펼친 자막을 확인했다. 1024×768 및 873×580에서 버튼과 인사 패널이 화면 안에 들어왔다. #1은 기존 기본 음소거를 UI로 켜고 시작 전 예상을 선택한 뒤 검사했다. #4는 안내 갱신 때 음성 컨트롤 노드를 보존해 재생/중지 표시와 자막이 유지되게 했다.
- #1·3은 실제 Chrome 네트워크 차단 뒤 신규 MP3의 재생 시간 증가(약 0.47/0.45초)를 확인했다. 이는 전체 게임의 오프라인 완주 검증은 아니다.
